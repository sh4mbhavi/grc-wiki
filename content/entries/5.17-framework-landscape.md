:::lede
Beyond ISO 27001 and the NIST family, most of the frameworks a GRC function
meets fall into four groups: **prescriptive control sets, governance models,
certifiable industry schemes, and national baselines**. Knowing which group a
framework belongs to tells you what it is for before you read a line of it.
:::

The field has more frameworks than any organisation should adopt. They overlap
heavily, because they are all describing the same small set of security
practices from different angles and for different audiences. The skill is not
knowing every framework in detail; it is placing a new one quickly — is this a
list of controls, a way of governing IT, a certification a customer will ask for,
or a floor a government has set — and then deciding whether it adds anything you
do not already have.

## Prescriptive control sets

Frameworks that tell you what to implement, in priority order.

:::terms
CIS Critical Security Controls :: 18 controls, each broken into safeguards, grouped into three Implementation Groups by organisation size and risk. Ordered by impact, so a small team can start at the top and stop where its resources run out. Covered at [5.8](/frameworks/cis-controls/).
CSA Cloud Controls Matrix :: A cloud-specific control set with mappings to most other frameworks, paired with the CAIQ questionnaire. The common reference for assessing a cloud provider.
OWASP ASVS / SAMM :: Application-security verification requirements and a maturity model for a secure development programme. Narrower scope, deep in one domain.
:::

## Governance models

:::terms
COBIT 2019 :: A framework for the governance and management of enterprise IT, from ISACA. It is broader than security — it covers IT value, resourcing and performance — and sits above a security control set rather than replacing one. Used where the question is "is IT as a whole well governed", often to satisfy audit committees.
ITIL 4 :: A service-management framework, not a security one, but its change, incident and problem practices are where several security controls actually live.
:::

:::def term="Certifiable framework" ref="5.0"
A framework an accredited or licensed third party can assess you against and
issue a recognised certificate or attestation for. ISO 27001, SOC 2, HITRUST,
PCI DSS and FedRAMP are certifiable in this sense; CSF 2.0, COBIT and the CIS
Controls are not.
:::

## Certifiable industry schemes

| Scheme | Sector and region | What it produces |
| --- | --- | --- |
| HITRUST CSF | US healthcare and its supply chain | A certification, at i1 or r2 assurance level, that maps many frameworks into one assessment |
| PCI DSS | Anyone storing or processing card data | An Attestation of Compliance; covered at [5.11](/frameworks/pci-dss/) |
| FedRAMP | Cloud services sold to US federal agencies | An authorisation (ATO) based on a tailored 800-53 baseline |
| TISAX | European automotive supply chain | A shared assessment result, based on an ISO 27001-derived catalogue |
| Cyber Essentials Plus | UK, any sector; required for some UK government contracts | A certificate based on a hands-on technical audit of five control areas |

HITRUST is the one worth understanding even outside healthcare, because its model
— take many overlapping frameworks, harmonise them into a single control set,
assess once, report against all of them — is the direction multi-framework
compliance is heading generally.

## National baselines

Governments set floors for their own suppliers and, often, for the wider
economy.

- **Cyber Essentials** (UK) — five technical control areas, self-assessed or,
  for Plus, independently tested. A baseline, not a comprehensive framework.
- **Essential Eight** (Australia) — eight mitigation strategies with a
  four-level maturity model, mandated for Australian government entities.
- **NIS2** (EU) — a directive, not a framework: it imposes risk-management and
  incident-reporting duties on operators of essential and important services,
  transposed into each member state's law.

These are obligations to meet, then build past — clearing Cyber Essentials or
Essential Eight Level Two is a starting position, not a security programme.

## Choosing between them

Pick the framework your buyers, regulators or sector already speak. A US
healthcare vendor is asked for HITRUST; a company selling to UK government needs
Cyber Essentials; an EU automotive supplier needs TISAX; a SaaS company selling
to North American enterprises is asked for SOC 2. Where nothing external
dictates the choice, ISO 27001 for a management system and the CIS Controls for
an implementation order is a defensible default that maps cleanly to almost
everything else. Adopt one primary framework, then use crosswalks — see
[5.2](/frameworks/building-a-crosswalk/) — to answer the rest from the same
evidence.

## Common questions

:::faq
### How many cyber security frameworks are there?

Dozens in active use, but they cluster into a few types: prescriptive control
sets (CIS Controls, CSA CCM), governance models (COBIT), certifiable schemes
(ISO 27001, SOC 2, HITRUST, PCI DSS, FedRAMP), and national baselines (Cyber
Essentials, Essential Eight). Most organisations need one primary framework and
crosswalks to the others.

### What is the difference between CIS Controls and NIST CSF?

The CIS Controls are a prioritised list of specific safeguards to implement. The
NIST CSF is a set of outcomes to assess against. CIS tells you what to do next;
CSF tells you how mature your programme is. They map to each other, and many
organisations use CSF for structure and CIS for the implementation order.

### What is HITRUST?

HITRUST maintains the HITRUST CSF, a control framework that harmonises ISO 27001,
NIST, PCI DSS, HIPAA and others into one set, and runs a certification scheme
against it. It is most established in US healthcare and its supply chain, where
customers frequently require HITRUST r2 certification from vendors.

### What is FedRAMP?

A US government programme that standardises security assessment and authorisation
for cloud services sold to federal agencies. A cloud provider works with an
accredited assessor against a FedRAMP baseline (derived from NIST SP 800-53) to
obtain an Authorization to Operate, which other agencies can then reuse.

### Which framework should a company start with?

If a customer or regulator names one, start there. If not, ISO 27001 for the
management system plus the CIS Controls for implementation priority is a solid
default that crosswalks to nearly every other framework, so later requirements
can be met from the same control work and evidence.
:::
