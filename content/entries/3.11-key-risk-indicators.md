:::lede
A key risk indicator is a **metric that warns that risk exposure is moving
toward, or past, appetite** - where a key performance indicator measures progress
toward an objective. A KRI is chosen to lead, so the warning arrives while there
is still time to act.
:::

The distinction is not simply leading versus lagging. What separates them is
subject: a KPI tracks performance against an objective, a KRI tracks the exposure
behind a risk. A KRI is then chosen so that it moves early - watching the drivers
of a risk while there is still time to act, rather than its residual score on the
register [3.1](/risk/reading-a-risk-register/) after the fact.

## How a KRI differs from a KPI

The two are routinely confused because both are numbers on the same dashboard.
They answer different questions: one tracks the exposure behind a risk, the other
progress toward an objective.

|  | Key risk indicator | Key performance indicator |
| --- | --- | --- |
| What it measures | Exposure moving toward a limit | Progress toward an objective |
| Direction in time | Chosen to lead - warns before the event | Usually lagging - records after |
| What it is tied to | An appetite threshold | A performance target |
| The question it answers | Is a risk building? | Was the objective met? |
| Example | Privileged accounts without MFA | Uptime achieved this quarter |

The same raw figure can serve as either, depending on what it is tied to. Uptime
against a target is a KPI; the number of near-misses trending up beneath that
uptime is a KRI.

## What makes a KRI worth having

Most indicators on a risk dashboard are neither leading nor actionable. Four
properties separate one that earns its place from one that fills a cell.

:::terms
Leading, not lagging :: It moves before the event it warns about, not after. A count of incidents already suffered is a scorecard, not an early warning.
Tied to a defined threshold :: A written level at which green becomes amber and amber becomes red. Without it the number has no meaning and can never be breached.
Owned by someone who can act :: A named person, not a function, who is accountable for the response when it breaches. An indicator no one owns is watched by no one.
Actionable :: A breach triggers a specific, pre-agreed response, not a discussion about whether to have one.
:::

## A worked example, tied to appetite

:::def term="Threshold (trigger level)" ref="3.2"
The level at which an indicator stops being informational and demands a response.
It is set relative to appetite [3.2](/risk/appetite-vs-tolerance/), so a breach
means exposure has moved to where the organisation already said it would act.
:::

Take a single control risk: privileged accounts left without multi-factor
authentication. The indicator is the proportion of privileged accounts with no
second factor, and appetite is expressed as bands - illustratively, green below
two per cent, amber at five per cent, red at ten per cent. The figures are
examples; the real ones come from what the organisation has decided it can carry.

Amber is where the indicator earns its place. Crossing it is not an incident, so
nothing has failed yet, but it triggers a named response: the account owner is
notified, the coverage gap is closed within a fixed window and if the figure
reaches red the exception is escalated to the risk committee. An indicator with
none of that wiring behind it is a colour on a slide.

## Where KRIs fail

**Chosen because they are easy to collect.** The indicator that is trivial to
pull from a system is rarely the one that predicts anything. Ease of collection
and predictive value are unrelated, and optimising for the first buys a
dashboard that measures nothing that matters.

**No threshold, so nothing ever triggers.** A number with no defined green,
amber and red cannot breach. It is reported, noted and forgotten, quarter after
quarter, because there is no line for it to cross.

**A dashboard of green that never moves.** Indicators that sit at green for a
year are either measuring a risk that is genuinely dormant or, far more often,
measuring the wrong thing. A board reporting pack [2.3](/governance/board-reporting/)
of unchanging green is a signal to re-examine the indicators, not reassurance.

## Common questions

:::faq
### What is the difference between a KRI and a KPI?
The difference is subject, not just timing. A KPI measures performance against an
objective; a KRI measures whether the exposure behind a risk is building. A KRI is
then deliberately chosen to lead, so it moves while there is still time to act,
where a KPI usually confirms an outcome already fixed. The same figure can be
either, depending on whether it is tied to a risk appetite threshold or a
performance target.

### How many KRIs should you have?
Few enough that each one is watched and acted on. A handful of indicators tied to
the risks the board actually cares about beats dozens that no one owns. If a KRI
has no defined threshold and no named owner, removing it loses nothing.

### How do you set a KRI threshold?
Work back from appetite. The red line sits where exposure would breach what the
organisation has said it will tolerate; amber sits far enough below it to leave
time to act before red. Both are judgements, so record who set them and revisit
them when appetite changes.
:::
