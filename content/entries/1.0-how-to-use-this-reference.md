:::lede
This is a reference work, not a course. Entries are numbered like clauses in a
standard so you can cite them, link into them, and find your way back.
:::

Six parts, each opening at `x.0` with what that part of the function actually
produces, then working outward. Every entry cites its sources, because a claim
about a framework is worth exactly as much as the thing it cites.

## Reading the numbering

The number before an entry is its clause. `3.2` is the second entry in Part 3;
`3.2.1` is the first section inside it. Every section heading is deep-linkable
twice — by its slug and by its clause number — so `#c3-2-1` and
`#the-difference-stated-plainly` reach the same place.

Clause numbers are stable. If an entry is retired the number is not reused, and
if the corpus is renumbered the old anchors redirect.

## Where to start

:::terms
You are new to the field :: Read 1.1, then 1.3, then 3.1. That is roughly ninety minutes and gets you to the point where a risk register makes sense.
You have an interview :: 1.4 for the boundary question, 3.2 for the vocabulary people get wrong, and Part 6 for the rest.
You have a specific question :: Search, or use the [A–Z index](/a-z/). The index uses inverted headwords, so "appetite, risk" and "risk appetite" both land.
You are building a programme :: Part 2 for the decisions, Part 4 for the obligations, Part 5 for the framework you have been asked for.
:::

## What this is not

It is not a substitute for the standard. Where an entry describes ISO 27001 or
the Trust Services Criteria, it describes them accurately and cites the clause,
but the certifiable text is the standard's and you will need a copy.

It is also not a template library. A few entries link to worked examples; most
describe how the artefact behaves and how it fails, which is the part that does
not come in a template.

## Corrections

Claims are checked against the standard they cite. Where an entry is wrong, it
is corrected against that source.
